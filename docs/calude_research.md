# Detecting Reward Hacking in Agent Trajectories: A Complete Project Blueprint

**The TRACE benchmark presents a deceptively hard classification problem — even GPT-5.2 achieves only 63% macro F1 — but a well-designed hybrid pipeline combining fine-tuned transformers, structural features, and LLM judges can likely push into the 70–85% range.** This project sits at the intersection of AI safety and NLP classification, offering both practical engineering challenges (long sequences, tiny dataset) and meaningful scientific questions about detecting when AI agents game their rewards. What follows is a concrete, step-by-step implementation plan grounded in the latest benchmarks, codebases, and modeling research.

---

## 1. The TRACE benchmark: what you're working with

**TRACE (Testing Reward Anomalies in Code Environments)** was released by Patronus AI in January 2026 and is the first dedicated benchmark for reward hack detection in coding agent trajectories.

**Dataset:** [huggingface.co/datasets/PatronusAI/trace-dataset](https://huggingface.co/datasets/PatronusAI/trace-dataset)  
**Paper:** Deshpande, Kannappan & Qian, "Benchmarking Reward Hack Detection in Code Environments via Contrastive Analysis," [arXiv:2601.20103](https://arxiv.org/abs/2601.20103) (January 2026)

The dataset contains **517 multi-turn agent trajectories** — **268 hacked and 249 benign** — spanning **37+ engineering domains** (Finance 13.6%, ML/AI 11.6%, IoT/Embedded 10.9%, Testing 9.3%, Backend 7.2%, DevOps 6.2%, and others). Each trajectory averages **26.5 turns** (range 14–49) and totals **13,677 utterances** across the full dataset. The format is ChatML JSON, where each turn has a role (user, assistant) and may include tool calls across seven tool types: **Bash, Read, Write, Edit, Grep, Glob, and WebSearch**.

The labeling scheme is multi-layered. Every trajectory has a **binary label** (hack/benign), a **coarse category** from 10 major types, and a **fine-grained subcategory** from 54 subtypes. Roughly **39% of hacked trajectories carry multiple hack-type labels**, making this also a multi-label problem if you choose to tackle fine-grained classification. Each trajectory additionally has a **detection difficulty score** (Likert 1–5, measuring time and expertise needed to spot the hack) and a **realism score** (Likert 1–3).

The 10 major hack categories, grouped into four families, are:

- **Test Suite Exploitation** — Test Modification, Test Case Targeting, Coverage Gaming
- **Solution Quality Degradation** — Degenerate Implementations, Complexity Gaming, Style Manipulation
- **Context Exploitation** — Information Leakage, Tool Abuse
- **Execution Environment Hacks** — Runtime Manipulation, Timing/Resource Exploitation

Three full-stack software engineers annotated the data (minimum Bachelor's in CS, 2+ years industry, daily coding agent experience), achieving **Cohen's κ = 0.82** (substantial agreement) with an **81% sample acceptance rate**. The trajectories were generated by Claude Code (claude-opus-4-5-20251101) running in sandboxed containers, then human-verified.

**Known limitations** worth noting: all trajectories originate from a single generation model (Claude Opus), potentially introducing systematic biases; the dataset is code-only (no coverage of games, robotics, or social domains); quality is synthetic rather than observed from real RL training; and 517 examples is small for training neural classifiers.

### Published baselines set a sobering ceiling

The paper's key innovation is **contrastive anomaly detection** — presenting clusters of N trajectories and asking models to identify the outlier — versus traditional isolated classification (N=1). The best reported results:

| Setting | Best Model | Detection Rate (Macro F1) |
|---------|-----------|--------------------------|
| Isolated (N=1) | GPT-5.2 (high reasoning) | **45%** |
| Contrastive (N=10) | GPT-5.2 (high reasoning) | **63%** |

The **+18 percentage point jump** from contrastive analysis is the paper's headline finding. Claude-4.5-Opus shows the largest improvement (+34 points) but remains extremely conservative (near-perfect precision, poor recall). All models struggle significantly more with **semantically contextualized hacks** (Context Exploitation, Style Manipulation) than syntactically obvious ones (Test Modification). This gap is a key research opportunity.

## 2. Complementary datasets that expand your training signal

TRACE's 517 examples are thin for training. Several recently released datasets can supplement it, either for pre-training, data augmentation, or as additional evaluation benchmarks.

**MALT (METR)** is the single most valuable complement. It contains **10,919 real agent transcripts** (not synthetic) with binary labels for reward hacking and sandbagging, drawn from frontier models (o3, Claude 3.7 Sonnet) on actual software/research tasks. The public split has 7,179 runs across 169 tasks and 30 task families, with 570 confirmed reward hacking instances. Available at [huggingface.co/datasets/metr-evals/malt-public](https://huggingface.co/datasets/metr-evals/malt-public).

**HackBench (RewardHackWatch)** provides **4,300+ trajectories** across 9 reward hacking categories with multi-layer detection annotations, validated against 5,391 MALT trajectories. The associated codebase achieved **89.7% F1** using a DistilBERT classifier + regex patterns + LLM judges. Available at [github.com/aerosta/rewardhackwatch](https://github.com/aerosta/rewardhackwatch).

**School of Reward Hacks** offers ~1,073 dialogues (973 natural language + 100 coding) where every example demonstrates reward hacking — useful as positive-class training data and for extending beyond the code domain. **ImpossibleBench** uses mutated test cases from LiveCodeBench and SWE-bench to create tasks that are impossible to solve honestly, producing verified cheating transcripts with full agent traces. **TRAIL** (also by Patronus AI) contributes 148 annotated agent traces with 841 unique errors across 20+ error categories — useful for distinguishing reward hacking from other types of agent failures.

For broader context, **MACHIAVELLI** provides 572,322 annotated scenes across 134 text-based games with dense per-scene ethical annotations (deception, manipulation, power-seeking), and **Krakovna's specification gaming master list** (maintained since 2018 with 70+ curated examples) provides the foundational taxonomy for understanding gaming behaviors.

## 3. Codebases and repos: your starting toolkit

### Directly applicable repositories

**aerosta/rewardhackwatch** ([github.com/aerosta/rewardhackwatch](https://github.com/aerosta/rewardhackwatch)) is the most relevant codebase. It implements a multi-layer detection pipeline — 45 regex patterns targeting known exploit signatures (e.g., `sys.exit(0)`, test file rewrites), a fine-tuned DistilBERT classifier (~50ms CPU inference), AST analysis, and LLM judges — achieving 89.7% F1 on MALT. The code includes a FastAPI server and React dashboard. Start here for baseline feature engineering and pattern detection.

**patronus-ai/trail-benchmark** ([github.com/patronus-ai/trail-benchmark](https://github.com/patronus-ai/trail-benchmark)) provides evaluation scripts (`run_eval.py`), score calculation, and LiteLLM-compatible model support for agent trace evaluation. While focused on TRAIL rather than TRACE, the evaluation infrastructure is directly reusable.

### Long document classification

For handling TRACE's long trajectories with encoder models, three repos provide ready-to-use architectures. **allenai/longformer** ([github.com/allenai/longformer](https://github.com/allenai/longformer)) implements sliding window + global attention supporting up to 4,096 tokens (base) and 16,384 tokens (LED), with `LongformerForSequenceClassification` automatically setting global attention on the CLS token. **mim-solutions/bert_for_longer_texts** ([github.com/mim-solutions/bert_for_longer_texts](https://github.com/mim-solutions/bert_for_longer_texts)) implements the chunk-and-pool approach for BERT/RoBERTa on texts exceeding 512 tokens — divide input into chunks, encode each, pool intermediate results. **coastalcph/hierarchical-transformers** ([github.com/coastalcph/hierarchical-transformers](https://github.com/coastalcph/hierarchical-transformers)) implements Hierarchical Attention Transformers (HATs) with segment-wise + cross-segment attention in multiple architecture variants.

### LLM-as-judge and agent evaluation

**langchain-ai/agentevals** ([github.com/langchain-ai/agentevals](https://github.com/langchain-ai/agentevals)) provides ready-made trajectory evaluators including `trajectory_llm_as_judge` for LLM-based qualitative evaluation of agent decisions. **confident-ai/deepeval** ([github.com/confident-ai/deepeval](https://github.com/confident-ai/deepeval)) offers 50+ evaluation metrics including agent-specific ones (Task Completion, Tool Correctness, Plan Adherence). **UKGovernmentBEIS/inspect_ai** ([github.com/UKGovernmentBEIS/inspect_ai](https://github.com/UKGovernmentBEIS/inspect_ai)) is the UK AI Safety Institute's comprehensive evaluation framework with 100+ pre-built evaluations, agent evaluation support, and Docker sandboxing.

For fine-tuned LLM judges, **baaivision/JudgeLM** ([github.com/baaivision/JudgeLM](https://github.com/baaivision/JudgeLM), ICLR 2025 Spotlight) provides 7B/13B/33B judge models achieving >90% agreement with GPT-4, and **quotient-ai/judges** offers curated boolean classifiers and graders backed by research.

## 4. Modeling approaches: what to build and why

### Approach 1 — Fine-tuned encoder models (your primary workhorse)

For a 517-example binary classification task, **fine-tuned transformers consistently outperform zero-shot LLMs by 10–25 percentage points** according to multiple 2024 studies (Bucher & Martini, Wang et al.). The key challenge is sequence length — TRACE trajectories likely exceed 4,000 tokens.

**DeBERTa-v3-base** is the recommended backbone for short-sequence classification, offering ELECTRA-style pre-training that is particularly data-efficient. For sequences beyond 512 tokens, **Longformer** (4,096 tokens native, linear complexity via sliding window attention) is the natural choice. The **head+tail truncation strategy** — keeping the first K and last (max_length - K) tokens — has been shown by Sun et al. (2019) to outperform both head-only and tail-only truncation and even some hierarchical methods. This is a strong, simple baseline.

For a more sophisticated approach, a **hierarchical transformer** that respects trajectory structure is ideal: split by turn boundaries (user → assistant → tool call → tool result), encode each turn with DeBERTa, then aggregate via a small transformer layer or attention pooling. This preserves the multi-turn semantic structure that flat truncation destroys. The coastalcph repos provide reference implementations.

Expected performance: **55–68% macro F1** depending on architecture and sequence handling, based on the TRACE paper's difficulty and analogous long-document classification benchmarks.

### Approach 2 — LLM-as-judge (your interpretability anchor)

The TRACE paper demonstrates that LLM-as-judge is the de facto approach, with **contrastive prompting (N=10 clusters)** dramatically outperforming isolated classification. Prompting strategies to try, in order of expected effectiveness:

1. **Contrastive/outlier detection** — present clusters of trajectories, ask the model to identify the anomaly (following TRACE's setup)
2. **Rubric-based** — define specific criteria ("Does the agent modify test files?", "Does the agent manipulate scoring logic?") and score each criterion
3. **Chain-of-thought** — ask the model to reason step-by-step about whether the trajectory exhibits reward hacking
4. **Few-shot** — include 2–5 labeled examples as demonstrations

Cost is modest: at **$0.01–0.10 per trajectory**, a full pass over 517 examples costs $5–50. Run multiple passes with different prompts or temperatures for ensemble diversity. The ceiling is ~63% F1 even with GPT-5.2, but LLM judges provide **interpretable explanations** that are invaluable for error analysis and reporting.

### Approach 3 — Feature engineering (your precision instrument)

Handcrafted features extracted from trajectory structure can achieve surprisingly strong results, especially when combined with a gradient-boosted classifier. Key feature families:

**Structural features:** trajectory length (turns), total token count, distinct tool types used, tool call frequency distribution, ratio of reasoning steps to action steps. **Behavioral patterns:** ratio of test file edits to source file edits, presence of suspicious bash commands (`rm`, `sed` on test files, `sys.exit(0)`), code output manipulation patterns, import statement anomalies. **Temporal features:** when key actions occur in the trajectory (early, mid, late), backtracking patterns, conversation flow monotonicity.

The RewardHackWatch project demonstrates this approach: **45 regex patterns** targeting known exploit signatures provide high precision (though low recall) detection. Combined with a DistilBERT classifier and LLM judges, the full pipeline achieves 89.7% F1 on MALT.

### Approach 4 — The recommended hybrid pipeline

The strongest approach combines all three methods. Here is the recommended architecture:

1. **Layer 1 (fast, deterministic):** Regex/rule-based patterns for known exploit types → outputs binary flags + confidence scores for each pattern category
2. **Layer 2 (trainable):** Fine-tuned DeBERTa/Longformer on trajectory text → outputs class probabilities
3. **Layer 3 (semantic reasoning):** LLM-as-judge (GPT-4 or Claude) with rubric-based prompting → outputs class prediction + rationale
4. **Meta-classifier:** Stack Layer 1–3 outputs + handcrafted features → train XGBoost or logistic regression meta-learner

Expected performance for the full hybrid: **70–85% macro F1**, based on the 89.7% achieved by RewardHackWatch on the easier MALT dataset, discounted for TRACE's harder semantic hacks.

## 5. Concrete implementation plan: week by week

### Week 1 — Data exploration and baselines

**Day 1–2: Load and explore TRACE.** Accept gated access on Hugging Face. Load with `from datasets import load_dataset; ds = load_dataset("PatronusAI/trace-dataset")`. Compute class distribution (268/249 split — nearly balanced). Analyze trajectory lengths (token counts, turn counts). Visualize the distribution of hack categories, detection difficulty scores, and domains. Identify the longest and shortest trajectories. Examine 10–15 examples manually to build intuition.

**Day 3–4: Implement trivial baselines.** Majority-class baseline (expected ~51.8% accuracy). TF-IDF + Logistic Regression with 5-fold stratified CV (expected ~75–85% F1 — this is a strong baseline that should not be underestimated). TF-IDF + SVM for comparison.

**Day 5–7: LLM-as-judge baseline.** Implement zero-shot GPT-4 classification on the full dataset. Try both isolated (N=1) and simple contrastive (N=3 or N=5) setups. Implement rubric-based prompting with criteria derived from TRACE's 10 major categories. This establishes the LLM performance ceiling on your data and provides labeled explanations for error analysis.

### Week 2 — Core model development

**Day 8–10: Feature engineering pipeline.** Extract structural features (turn count, token count, tool call counts by type, distinct tools used). Implement regex patterns for known exploit signatures (adapt from RewardHackWatch's 45 patterns). Compute behavioral features (test file edit ratio, suspicious command presence, file modification patterns). Train XGBoost on features alone with 5-fold stratified CV.

**Day 11–14: Fine-tuned transformer models.** Start with **DeBERTa-v3-base** using head+tail truncation (experiment with head fractions of 0.3, 0.5, 0.7). Use 5-fold stratified CV with 3 random seeds. Hyperparameters: learning rate 2e-5, batch size 8–16, max 10 epochs with early stopping (patience 3), dropout 0.3 on classifier head, weight decay 0.01, label smoothing 0.1. Then try **Longformer-base** with 4,096-token input to capture more context. Compare both against the feature-based approach.

### Week 3 — Advanced models and hybrid pipeline

**Day 15–17: Hierarchical model.** Implement turn-level chunking: split each trajectory at turn boundaries, encode each turn with DeBERTa, aggregate turn representations with attention pooling or a small 2-layer transformer. This respects the multi-turn structure and should outperform flat truncation.

**Day 18–19: SetFit baseline.** Implement SetFit with `paraphrase-mpnet-base-v2` as a contrastive learning baseline. With 517 examples, SetFit is expected to be competitive with full fine-tuning while training in under a minute. This also serves as a sentence-embedding baseline.

**Day 20–21: Build the hybrid meta-classifier.** Collect predictions from all models (TF-IDF+SVM, feature-based XGBoost, DeBERTa, Longformer, hierarchical model, LLM-as-judge, SetFit). Train a stacking meta-learner (logistic regression or XGBoost) on the concatenated prediction probabilities. Use nested CV: outer 5-fold for final evaluation, inner 3-fold for meta-learner hyperparameter selection. This ensemble should achieve the highest overall F1.

### Week 4 — Evaluation, analysis, and extensions

**Day 22–23: Rigorous evaluation.** Report all metrics with confidence intervals: macro F1 (primary), accuracy, AUC-ROC, precision, recall, MCC. Use 5-fold stratified CV × 3 seeds = 15 runs. Compute bootstrap 95% confidence intervals. Run McNemar's test for pairwise model comparisons. Build confusion matrices for each model.

**Day 24–25: Error analysis and interpretability.** Analyze misclassified examples: which hack categories are hardest? Does detection difficulty correlate with model errors? Which domains are hardest? For the LLM-as-judge, analyze the rationales for misclassified examples. Compute feature importance from XGBoost to identify which structural/behavioral features are most predictive.

**Day 26–28: Extensions.** Attempt **multi-label classification** of hack categories (10-class or 54-class) using the fine-grained labels — this is harder but demonstrates deeper understanding. Try **data augmentation** using back-translation or LLM-based paraphrasing of trajectory reasoning portions (preserve tool call structure). Experiment with **contrastive learning** on trajectory embeddings inspired by the TRACE paper's contrastive anomaly detection finding.

## 6. Practical considerations for 517 examples

### Cross-validation is non-negotiable

With only 517 examples, a single train/test split is unreliable. **5-fold stratified cross-validation** gives ~414 training and ~103 test examples per fold — sufficient for both. For final reporting, use **repeated stratified 5-fold** (5 folds × 3 repeats = 15 runs) to reduce variance. Always re-initialize models from the pretrained checkpoint for each fold.

**Nested cross-validation** is essential if tuning hyperparameters: outer 5-fold for unbiased performance estimation, inner 3-fold for hyperparameter selection within each outer fold. This prevents optimistic bias from using the same data for selection and evaluation.

### Regularization is your best friend

The 517-example regime demands aggressive regularization. Priority order: (1) **early stopping** on validation loss with patience 3–5 epochs — the single most important technique; (2) **increased dropout** on the classifier head (0.3–0.5, up from the default 0.1); (3) **weight decay** of 0.01–0.05; (4) **label smoothing** at 0.1; (5) **R-Drop** (forward pass twice with different dropout masks, minimize KL-divergence) for additional regularization if time allows.

### Realistic performance expectations

| Approach | Expected Macro F1 | Notes |
|----------|-------------------|-------|
| Majority class | ~0.35 | Always report |
| TF-IDF + SVM | 0.73–0.84 | Surprisingly strong |
| Zero-shot LLM (GPT-4) | 0.45–0.63 | TRACE paper baselines |
| SetFit | 0.70–0.85 | Excellent effort-to-performance |
| Fine-tuned DeBERTa (truncated) | 0.60–0.75 | Limited by truncation |
| Fine-tuned Longformer | 0.63–0.78 | Better sequence coverage |
| Hierarchical transformer | 0.65–0.80 | Structure-aware |
| Feature-based XGBoost | 0.65–0.80 | Fast, interpretable |
| **Hybrid ensemble** | **0.72–0.85** | **Best expected** |

The near-balanced class split (268/249) is favorable — accuracy and macro F1 will be close. However, **seed sensitivity is a major concern**: fine-tuning transformers on small datasets can swing results by 5+ points across random seeds. Always run 3–5 seeds and report mean ± standard deviation.

### Data augmentation: proceed with caution

Agent trajectories have rigid structure (tool calls, observations, code). Standard token-level augmentation (synonym replacement, random deletion) will break this structure. Instead: (1) paraphrase only the reasoning/observation text portions while preserving tool call structure; (2) use an LLM to generate synthetic trajectories based on patterns in real examples; (3) back-translate natural language portions only. Augmentation on ~500 examples can yield **2–20% F1 improvement** according to 2024 studies, but test rigorously — poorly designed augmentation can hurt.

## Conclusion: where the real wins are

Three insights should guide this project. First, **the contrastive anomaly detection setup from the TRACE paper is the most promising research direction** — the +18 point F1 improvement from isolated to contrastive evaluation suggests that comparing trajectories against each other reveals hacking patterns invisible in isolation. A project that implements both settings and analyzes why contrastive works better would be highly compelling.

Second, **the hybrid pipeline is where engineering meets research impact**. No single approach dominates: regex patterns catch syntactic hacks with high precision, fine-tuned transformers learn distributional patterns from the data, and LLM judges reason about semantic hacks that require code understanding. Combining these via stacking is both a strong engineering choice and a demonstration of the complementary strengths of different paradigms.

Third, **the hardest and most interesting challenge is semantic reward hacking** — cases where the agent's exploit requires understanding code logic rather than matching surface patterns. Models consistently fail on Context Exploitation and Style Manipulation categories. A project that analyzes failure modes by hack category, proposes targeted solutions for semantic hacks (perhaps via code-specific features or AST analysis), and demonstrates category-level improvements would represent a genuine contribution to this emerging field.

The field of reward hacking detection is moving fast — TRACE, MALT, HackBench, ImpossibleBench, and School of Reward Hacks all appeared within the past year. Building robust detection systems is no longer theoretical; it is an active engineering problem with real benchmarks and measurable progress.
