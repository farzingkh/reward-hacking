## 2. Approach

**Primary (critical path) — Approach A: turn-aware transformer.**
A small transformer encoder over the sequence of *per-turn* Qwen3-Embedding-0.6B vectors, with role and position embeddings and a learnable [CLS] token. Trained on the same 60/20/20 split as MS3 with weighted BCE and tuned threshold, so the comparison to MS3 is apples-to-apples.

**Stretch (only if A is done by Thu 5/7) — Approach B1b: SupCon + BCE multi-task fine-tune.**
LoRA fine-tune of Qwen3-Embedding-0.6B with a multi-task loss (Supervised Contrastive + BCE) on truncated 8K-token trajectories. Re-extract embeddings, re-train A on top, compare. SupCon (Khosla et al., 2020) is chosen instead of self-supervised InfoNCE because the unified training set is too small (~1,070 trajectories) for self-supervised contrastive to learn useful structure.

B1b runs behind explicit go/no-go gates (Section 5.2). Even a negative result is reported honestly: "fine-tuning on ~1K trajectories did not improve over frozen embeddings" is a legitimate scientific claim.

## 3. Modeling spec — Approach A

### 3.1 Inputs

- **Per-turn embeddings.** Re-run Qwen3-Embedding-0.6B once per turn (each turn becomes one 1024-d vector). Cache to disk as `data/per_turn_embeddings/<source>/<traj_id>.npz` with shape `(num_turns, 1024)`. ~47K turn embeddings total at ~26.5 turns/traj × 1,780 trajectories.
- **Role labels.** Map each turn to one of {`user`, `assistant`, `tool_call`, `tool_result`}. Same source-specific parser logic as MS3.
- **No turn-level truncation.** Pad each batch to its longest trajectory; use attention mask. Safety cap `max_turns=512` only kicks in for pathological MALT outliers (verify against the data before training).

### 3.2 Architecture

```
input: (B, T, 1024) per-turn Qwen3 embeddings + role IDs (B, T) + mask (B, T)
  ↓
Linear(1024 → 256) projection
  + role_embedding(4 → 256)
  + learned absolute position_embedding(max_turns → 256)
  ↓
prepend [CLS] token (learnable, 256-d)
  ↓
2× TransformerEncoderLayer(d=256, heads=4, ffn=1024, dropout=0.3, pre-norm)
  ↓
take [CLS] output
  ↓
LayerNorm → Dropout(0.5) → Linear(256 → 1)
  ↓
logit (BCE-with-logits)
```

~1.5M trainable parameters.

### 3.3 Training

- Loss: `BCEWithLogitsLoss(pos_weight=N_neg/N_pos)` on the unified train set (84/16 imbalance).
- Optimizer: AdamW, lr=3e-4, weight_decay=0.01.
- Scheduler: cosine with 5% warmup, 50 max epochs.
- Batch size: 32. Early stop on val F1, patience=8.
- 3 random seeds {17, 42, 1337}, report mean ± std on test.
- Threshold: tune on val for max F1. Same protocol as MS3.

### 3.4 Splits

Identical to MS3 (60/20/20, same seed). Required for fair comparison.

### 3.5 Evaluation

| Eval | Purpose |
|---|---|
| Headline metrics on test | AUC, F1, P, R at tuned threshold, MCC. Direct comparison row vs MS3 ProbeMLP. |
| Per-source breakdown | Same metrics on TRACE / MALT / RRH / Corpus test slices. |
| Per-category breakdown | TRACE-only, by 10 coarse hack codes (1.1.x ... 4.2.x). |
| Confusion matrix | Overall + per-source. |
| Length-bucketed F1 | F1 across trajectory-length quartiles. Tests whether turn-awareness helps long trajectories specifically. |
| Early-detection eval | Re-evaluate trained model on test trajectories truncated to first 16 / 32 / 64 turns. Tells the deployment-time story without baking truncation into training. |
| Ablation: turn-aware vs MS3 ProbeMLP | Same test set, same seed, controlled comparison. Headline result. |
| Attention rollout viz | For 4 hand-picked examples (1 TP, 1 TN, 1 FP, 1 FN), show which turns the [CLS] token attended to. |

## 4. Modeling spec — Approach B1b (stretch)

### 4.1 Setup

- LoRA (rank=16, α=32) on q/k/v/o + ffn projections of Qwen3-Embedding-0.6B.
- 4-bit base via bitsandbytes; gradient checkpointing; flash-attention-2.
- Truncate inputs to **8K tokens at training time** (down from 32K at inference). Acknowledge train/eval mismatch as a limitation in the report.

### 4.2 Loss

`L = α · SupCon(z, τ=0.1) + (1 − α) · BCE(linear(z))`, α=0.5 fixed initially.

`z` is the pooled trajectory representation (last-token via left-padding, same as MS3). The classifier head is linear over `z`.

### 4.3 Batch construction

Class-balanced: target 8 hacked + 8 benign per batch (16 total). Drop to 4+4 (8 total) if 16 OOMs at 8K context. SupCon requires both classes in every batch; smaller-than-4+4 batches are not viable.

### 4.4 Training

- 3 epochs over unified train set (~1,070 trajectories → ~3,200 steps at batch 16).
- LR: 1e-4 on LoRA, 3e-4 on classifier head; AdamW; weight_decay=0.01; warmup 10%.
- Wall-clock estimate: 8–12 hours on RTX 5070 Laptop (12GB), allowing for thermal throttling. Run overnight Wed→Thu.

### 4.5 Eval

Re-extract trajectory embeddings (32K context, no truncation) using fine-tuned Qwen3. Re-train Approach A's turn-aware classifier *unchanged* on top. Compare to A. Report deltas.
